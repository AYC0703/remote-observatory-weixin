> **核查方式**：所有金额与尺寸均可由原文复算；图纸类结论已通过直接读图确认。

## 组 1：经费数字自相矛盾（最严重，可逐项复核）

同一个项目的经费在文档中出现了 **5 个互不相容的数字**：

| 出处 | 数字 |
| --- | --- |
| 封面「项目基本信息表 → 申请经费」 | **¥28,638** |
| 第九章「合计」 | **¥14,729** |
| 第九章「本项目申请经费」 | **¥9,251** |
| 经费预算明细表「合计」行 | **¥28,638** |
| 明细表八项小计逐行相加 | **¥14,729** |
| 明细表各行金额逐行相加（修正两处小计后） | **¥14,909** |

### 1.1 封面 ¥28,638 与第九章 ¥14,729 矛盾，差额 ¥13,909

- 封面：申请经费 **¥28,638**
- 第九章：合计 **¥14,729**，本项目申请经费 **¥9,251**
- 两者相差 **¥13,909**，且这一差额无法由任何一组设备/材料项解释。

### 1.2 明细表「合计 ¥28,638」与表内八项小计之和 ¥14,729 不符

按明细表**自己写出的小计**相加：

```
设备费 5478 + 结构材料 2590 + 外协加工 1930 + 驱动传动 960
+ 电子控制 581 + 网络监控 1500 + 安全配套 690 + 备用金 1000
= 14729
```

即表内小计之和是 **¥14,729**（与第九章一致），但该表**打印的合计是 ¥28,638**。
**¥28,638 无法由表内任何一组数字推出**——它不是小计之和、不是小计之和的倍数、也不是任何两类的组合。

### 1.3 「结构材料小计 ¥2,590」少算 ¥300

按明细表结构材料类各行的**小计列**逐行相加：

| 行 | 小计 |
| --- | --- |
| 5052 铝镁合金板 1.2mm | 640 |
| 铝方管 30×30×2 | 208 |
| 工业铝型材 4040 | 384 |
| 工业铝型材 2020 | 144 |
| 顶部承力盘 φ1200×3mm | 260 |
| 塔身覆面板 1.5mm 镀锌钢板 | 220 |
| 镀锌矩形管 100×50×3 | 456 |
| L50×50×4 角钢 | 128 |
| 五金件 | 180 |
| 护栏 φ32 圆钢 | 270 |
| **合计** | **2,890** |

表内写 **2,590**，**少 ¥300**。

### 1.4 「安全配套小计 ¥690」多算 ¥120

| 行 | 小计 |
| --- | --- |
| 接地极 + 扁铁 + 等电位端子箱 | 180 |
| 剩余电流保护 + 二级浪涌保护 | 120 |
| 光伏降级方案备件（数量 0） | 0 |
| 密封胶 / 结构胶 / EPDM 胶条 / 耐候胶 | 150 |
| 标识牌、科普标语、安全使用说明牌 | 120 |
| **合计** | **570** |

表内写 **690**，**多 ¥120**。

### 1.5 修正后的正确合计应为 ¥14,909

```
5478 + 2890 + 1930 + 960 + 581 + 1500 + 570 + 1000 = 14909
```

即：**封面与明细表的 ¥28,638 错、明细表两处小计错、正文第九章的 ¥14,729 是「表内小计之和」而非「真实合计」。**

### 1.6 「其中望远镜 ¥5,398 单列」口径与 ¥9,251 不匹配

§9.3 写：「望远镜整机 ¥5,398 单列……本项目申请经费 ¥9,251」。

- 按「仅望远镜单列」：`14729 − 5398 = 9331 ≠ 9251`
- 按「设备费整类单列」：`14729 − 5478 = 9251` ✅

差的那 **¥80** 是设备费第二行的「12V/3A 电源适配器 + Type-C 线」。
**¥9,251 的算法是对的，但 §9.3 的表述应为「设备费 ¥5,478 单列」。**

### 1.7 备用金「约 8%」未给出计算基数

明细表第八类写「不可预见费（约 8%）」= ¥1,000。反算：

| 基数 | 实际比例 |
| --- | --- |
| 13,729（小计之和 − 备用金） | 7.28% |
| 14,729（小计之和） | 6.79% |
| 14,909（真实合计） | 6.71% |

**均不等于 8%**。若要正好 8%，基数应为 ¥12,500。建议注明基数或改为「约 7%」。

## 组 2：逻辑冲突与自相矛盾

### 2.1 「下雨自动关罩 ≤10s」与「全关 ≤35s」不可能同时成立

第八章指标：

| 指标 | 目标值 |
| --- | --- |
| 单程开合时间 | 全开 ≤40s，全关 ≤35s |
| 下雨自动关罩响应时间 | **≤10s（雨感触发到动作完成）** |

而 §4.6(4) 自述「全关约 25s」。若「动作完成」指**关罩到位**，则不可能 ≤10s。
**必须明确定义**：≤10s 是指「雨感到开始动作」，还是「雨感到关罩到位」。若为前者，应与「全关 ≤35s」合并表述。

### 2.2 雨感「连续 3 次触发」未给采样周期，10s 指标无法验证

若采样周期 1s，仅判定本身就要 3s；若 0.5s 则 1.5s。**判定窗口未定义 → 指标不可测。**

### 2.3 状态机 S5 保护态的迁移重复且自相矛盾

§4.9 表格中：

| 状态 | 动作列 | 迁移列 |
| --- | --- | --- |
| S5 保护态 | 「强制中止当前动作，**立即关罩**并告警」 | 「环境恢复正常且持续 5min → **回到 S4 关罩** → 迁移至 S4」 |

**若 S5 已经「立即关罩」，就不应该再回到 S4 去关罩。** 图纸 03(d) 的状态机图同样画成 `S5 → 环境恢复5min → S4 关罩中`。
**S5 究竟是「动作态」（正在关罩）还是「结果态」（已关罩并锁定）没有定义。** 若为结果态，恢复后应迁移至 **S1 闭合待机**。

### 2.4 INA226 的 3A 阈值与自身电源计算冲突

- §4.6(5)：堵转保护「INA226 电流 **>3A 持续 2s** 断电」
- §4.6(6)：「2 台推杆**堵转峰值 240W**」→ `240W / 24V = 10A`（单台约 5A）

1000N/24V 推杆的额定工作电流通常在 3~5A，启动冲击可达 8~10A。
**若单台正常电流已接近或超过 3A，则 3A 阈值会在正常启动时误触发保护。两者必有一错。**

### 2.5 通信失联时的行为完全未定义

全文**未出现**「失联 / 断网 / 离线 / 心跳 / 重连」任何一个词。

公共 MQTT Broker 一旦不可达（校园网抖动、4G 掉线、公共节点重置），以下问题均无规定：

- 罩子停在什么状态？
- 是否会因为超时误判而自动关罩、打断正在进行的整晚曝光？
- 如何告警？谁来处理？

| 内容 | 正文 §4.1 | 图 03(c) |
| --- | --- | --- |
| 4G 旁路 | ✅ 应用层列出 | ❌ 未画出 |

### 2.7 「远程控制成功率（校园网内）≥95%」与 §4.8 架构矛盾

§4.8 明确**不使用校园网内网后端**，而是「公共 MQTT + 校园网 + 4G 旁路」。
指标却限定「校园网内」。**测试口径与架构描述不符。**

- 项目周期：14 周（2026-10 ~ 2027-01）
- P5 系统集成：第 11–12 周；P6 观测与展示：第 13–14 周

留给连续运行的时间最多约 **14 天**，与「30 天连续值守」不符。需说明是否提前挂机、或调整指标表述。

## 组 3：安全设计缺项（红线级，上屋顶前必须解决）

### 3.1 ⚠️ 限位开关接法与失效安全原则相悖（最高优先级）

**图 02(d) 原文**：

| 编号 | 名称 | 说明文字 |
| --- | --- | --- |
| ① | 推杆内置 | 行程末端自断电 |
| ② | 机械微动 | **SS-5GL ×2~3 常开串入回路** |
| ③ | 软件限位 | 行程计数 + 60s 超时停机 |
| ④ | 堵转保护 | INA226 >3A 持续 2s 断电 |
| ⑤ | 急停回路 | **常闭**按钮串在驱动器电源 |

**两个问题：**

1. **表述自相矛盾**：「常开触点**串入**电机回路」字面意思是回路常态断开 → 电机永远无法得电。若本意是「到位时闭合给出信号」，则它不在电机回路里。
2. **若确为常开接法，属失效危险（fail-dangerous）设计**：限位线一旦断开、接头氧化、开关进水，系统读到的永远是「未到位」 → 继续运行 → **直接撞到底**。

**安全限位必须用常闭（NC）接法**：断线即等效「已到位」 → 停机。

> 同图的 ⑤ 急停写的是「常闭」，说明作者知道常闭才是安全侧——**②的「常开」大概率是笔误，但图纸与正文都未澄清，必须确认后才能接线。**

### 3.2 全文没有任何手动/机械应急开合方式

搜索全文：**「手动」「手摇」「应急」「脱开」四个词均未出现**。

断电、驱动器烧毁、固件刷废、MCU 死机时，罩子如何打开或关闭？
对「无人值守 + 夜间 + 屋顶」的场景，**手摇柄或快速脱开插销是必需项**。

### 3.3 无接闪器（避雷针）

§4.10 只做了「等电位 + 接地极接地电阻 ≤10Ω」。

塔顶是 **1.6m 高的全金属球壳**，位于校园制高点。**只做接地、不做接闪，等于把雷电流直接引到设备与结构上。**
明细表安全配套类中亦**无接闪器条目**。

> ⚠️ **选址改为楼顶后本条风险显著升级**，且「自打独立接地极」的做法在楼顶可能违反防雷规范 —— 见 **9.2**。

### 3.4 急停按钮的安装位置未定义

明细表仅写「急停按钮（常闭）+ 安全警示标签 ¥20，串在驱动器电源回路」。
若装在塔顶控制箱内，**地面人员发现危险时无法触及**。应明确装在**塔下人员可达处**。

### 3.5 雨感保护是软件路径，MCU 死机即失效

§4.9 中雨感由 ESP32 读取并参与状态机判断，属**纯软件路径**。
**ESP32 死机 / 固件跑飞 / 程序卡在某处时，雨感保护同时失效。**
建议增加一路**不经过 MCU 的硬件互锁**（雨感继电器直接切断或反转驱动器使能）。

### 3.6 「露点加热」有描述无器件

- §4.10：「壳内温度低于露点 2℃ 时启动小功率加热」
- §4.2 表格：「依托 S50 Pro 机内加热元件」

但 S50 Pro 的机内加热是**给镜片除露**的，**不能给整个壳体除湿**。
且明细表标准版中**没有任何加热膜/加热器条目**（仅高配版提到「温湿度闭环 + 自动除露」）。

### 3.7 推杆冬季结冰无对策

§4.9 的保护阈值含「温度 <-8℃」，说明预期冬季运行。
但 §10.2 风险表中「球壳下滑卡滞」的应对只有「加滑块 / 推杆先慢后快 / 电流保护 / 60s 超时」——**均不解决推杆伸缩杆结冰卡死**。

### 3.8 「光栅或地感提示」在预算中无对应物品

§4.10 人身安全写「球壳下滑路径下方严禁站人（**设光栅或地感提示**）」。
明细表中**没有任何光栅/地感条目**。

### 3.9 推杆自锁性未说明

断电瞬间球壳是否会因自重下滑或坠落，取决于推杆是否自锁：

| 丝杆类型 | 自锁性 |
| --- | --- |
| 梯形丝杆（多数 1000N 推杆） | 通常自锁 |
| 滚珠丝杆 | **不自锁**，需抱闸 |

**选型参数中未说明丝杆类型**，而这是「断电安全性」的关键。

## 组 4：工程计算与参数问题

### 4.1 ⚠️「镜筒顶 1368mm」依赖尚未确认的三脚架高度，且可行域不成立

**1368 的推导链**（来自图 01(C) 与 §4.4）：

```
托板标高 650 + 三脚架展开高度 450 + 镜筒高 268 = 1368
```

而图 01 自己注明：三脚架展开高度「官方未公布（**420~520mm**），按典型值 450mm 绘制」。

**可行域校核**（约束：镜筒顶 ≤ 罩顶 − 150 = 1450）：

令托板标高 `h ∈ [550, 750]`（650±100），三脚架高 `t ∈ [420, 520]`：

```
h + t + 268 ≤ 1450   →   h + t ≤ 1182
```

| 情形 | 结果 |
| --- | --- |
| t = 520（上限），h = 650（设计值） | 650+520+268 = 1438，净空 162mm，**仅余 12mm** |
| t = 520，h = 750（托板上限） | 需 t ≤ 432 → 落在 420~432 的**极窄区间** |
| t = 520，h = 750，若 t 实际 = 450 | 750+450+268 = 1468 > 1450，**净空 132mm，不达标** |

**结论：托板 ±100mm 的可调范围与「净空 ≥150mm」在最不利组合下不成立。**
文中只说「到货后现场实测标定」，**没有给出标定的约束式与可行域**——建议补上 `h ≤ 1450 − t − 268` 这一条硬约束。

### 4.2 校核 B 中「主机半宽 84.5」出处不明

§4.4 与图 01 均写「R500 − 主机半宽 **84.5** = 403」。

已知机身 140×149×268：

| 取法 | 值 |
| --- | --- |
| 140 / 2 | 70 |
| 149 / 2 | 74.5 |
| 机身对角半径 √(140²+149²)/2 | 102.2 |
| **文中采用** | **84.5** ← 无法由给定参数推出 |

若改用三脚架 φ263 的半径 131.5 作为**方位旋转扫掠半径**，则侧向余量 = 500 − 131.5 = **368.5mm**（仍 ≥300mm 指标，但与文中 403mm 差 34.5mm）。
**建议明确「旋转包络半径」的取值依据。**

### 4.3 ⚠️ 护栏高度可能与「方位 360°、仰角 ≥15°」指标冲突

**已知条件**：

| 项 | 值 |
| --- | --- |
| 护栏 | φ32 圆钢，背向扇区 270°，**高 600** |
| 承力盘 | φ1200（外缘半径 600mm），标高 1100mm |
| 望远镜入瞳高度 | ≈1368mm（镜筒顶） |

**计算**（假定护栏自承力盘面 1100 起算，则护栏顶标高 1700mm；望远镜在盘中心，视线水平距离 600mm 到护栏）：

```
视线在护栏处的高度 = 1368 + 600 · tan(θ)  >  1700
→ tan(θ) > 0.5533
→ θ > 28.96°
```

**即：方位角落在护栏 270° 扇区内的方向，仰角低于约 29° 就会被护栏遮挡。**

这与第八章指标「仰角 ≥15°，方位 360°」**直接冲突**。
（若「高 600」另有所指——例如自室外地坪起算——请补充标注基准，并说明护栏顶的实际标高。）

### 4.4 结构校核风速 = 保护动作风速 = 8m/s，零裕度

| 出处 | 风速取值 |
| --- | --- |
| §4.6(2) 结构强度校核 | 8 m/s（q=38.4Pa） |
| §4.9 保护动作阈值 | **风速 >8m/s 强制关罩** |

**保护动作发生时风速必然已超过 8m/s**，而结构只按 8m/s 校核。
建议结构校核取保护阈值的 **1.5~2 倍（12~16 m/s）**，或明确说明两者的裕度关系。

> ⚠️ 原 8m/s 是按**地面空地**取的。选址改为楼顶后风场完全变化，须按风压高度变化系数重算 —— 见 **9.4**。

### 4.5 风载叠加口径不清

§4.6(3)：`F ≥ 3 × 自重 + 风载 + 摩擦 ≈ 173N`

- 自重 48N、摩擦 10N 是**竖直**方向分量
- 风载 19N 是**水平**方向

把水平风载直接加到竖直推力需求上，**物理口径不成立**（水平风载主要由导轨承受，转化为竖直阻力仅为摩擦分量 `μ·F_wind ≈ 0.15 × 19 ≈ 2.9N`）。
当前算法**偏保守（结果安全）**，但会让「安全系数 5.8×」的含义被高估或误读。建议说明受力方向与叠加依据。

### 4.6 推杆安装几何完全缺失

§4.6 只给出两个标量：**推力 173N、行程 520mm**。

**缺失的关键几何参数**：

| 缺失项 | 为什么重要 |
| --- | --- |
| 收拢长度（安装距） | 行程 560mm 的推杆收拢长度通常 760~810mm，**需在塔身外壁找到安装空间** |
| 铰点位置 | 决定推杆与导轨的相对关系 |
| **推力方向与滑动方向的夹角 θ** | 有效推力 = `F · cos θ`，θ 未定义则安装可行性无法验证 |
| 推杆是「推」还是「拉」 | 决定自重是助力还是阻力 |

**这是结构与驱动之间缺的一环，建议补一张推杆安装几何图。**

### 4.7 「1000N 且 20mm/s、¥320」的参数与价格可能不匹配

- §4.6(4)：推杆速度「约 20mm/s」
- 明细表：单价 **¥320**

1000N 级电动推杆通常速度为 **5~15mm/s**（大推力必然低速）。**20mm/s 且 IP65 的 1000N 推杆较罕见，价格通常高于 ¥320。**
若实际速度低于 20mm/s，「全开 26s / 全关 25s」的推算不成立，需重新对照「≤40s / ≤35s」指标。

### 4.8 推杆行程 560mm 与所需行程 520mm 的关系未说明

选 560mm、需 520mm，**余量 40mm 本身是合理的**（推杆行程应大于所需行程），但文中未作解释，容易被审阅者当作矛盾。

### 4.9 24V 电力电缆未计入预算，线径未校核

明细表仅有「屏蔽线 / 磁环 / 端子 / 散热片 1 批 ¥50」。

**从市电配电箱到塔顶的 24V 主供电电缆是一个独立条目**：

- 若距离 20m、电流 5A、要求压降 <5%，需 **≥2.5mm² 铜芯**
- 该电缆既**无预算条目**，也**无线径校核**

> ⚠️ 选址改为楼顶后，「校园路灯回路」取电方案失效，需从楼内配电间引一路上楼顶 —— 见 **9.3**。

### 4.10 导轨抗倾覆能力未校核

§10.2 写「导轨每 **500mm** 加滑块」，但滑动行程仅 **520mm**——实际只能布置约 1 组滑块间距。

球壳承受水平风载产生的**倾覆力矩由滑块承担**，而文中**未给出滑块的许用载荷与间距校核**。

### 4.11 关键路径风险：S50 Pro 到货时间未纳入风险表

- P1（第 1–2 周）：「S50 Pro **到货**点验」
- 而托板标高、承力盘开孔、井道尺寸**均依赖实测三脚架高度**（§4.4 注、图 01 注）

**若望远镜延迟到货，P2（第 3–6 周）的承力盘加工与井道就无法定尺寸。**
§10.2 风险表中**没有这一项**——这是本项目最可能发生的进度风险。

### 4.12 球壳 φ1000 与塔身 φ800 的配合未进入尺寸链

明细表写塔身覆面板「**φ800**×1100 展开」，球壳 R=500（**φ1000**）。
球壳下滑时须从塔身外侧套下，单边间隙 100mm。

正文 §4.4 尺寸链表中**没有出现 φ800**，读者无法自行验证是否会与塔身、滑块、护栏干涉。**建议把塔身直径、滑块厚度、球壳内表面间隙列入 4.4 尺寸链表。**

## 组 7：架构与安全模型问题（技术路线层面最重要的一条）

### 7.1 ⚠️ 使用公共 MQTT Broker 控制机械装置，安全模型不成立

**§4.8 原文**：

> 不在校园里自建服务器、不占用学校小程序/后端资源。控制端直接用 ESP32-S3 固化的 MQTT 客户端，接入**公共 MQTT Broker（如巴法云或 EMQX 公共节点）**；学生终端用网页面板/MQTT 客户端/校园小程序（**前端直连 Broker**）均可，无需后端托管。

**逐条风险：**

| # | 风险 | 说明 |
| --- | --- | --- |
| 1 | **公共节点定位是测试用途** | EMQX 公共节点（`broker.emqx.io`）官方明确不保证可用性、不保证隔离、随时可能重置。用它控制会夹伤人的屋顶机构不可接受 |
| 2 | **弱鉴权 / 主题空间共享** | 巴法云等公开节点通常鉴权薄弱。一旦主题名可猜，**任何人都能发布开罩指令** |
| 3 | **前端直连 = 凭证即控制权** | 「前端直连 Broker」意味着 MQTT 用户名/密码必须下发到每个学生的手机与浏览器。**无法回收、无法按人审计、无法限权** |
| 4 | **浏览器直连的网络障碍** | 需 MQTT over WebSocket；校园网通常封非标端口。改用 WSS 则需要域名与证书 |
| 5 | **无 SLA** | 公共节点无可用性承诺。半夜自动观测依赖它开/关罩不可接受 |
| 6 | **无审计** | 公共节点不提供可追溯的操作日志 |

**建议路线**：

- **私有 Broker + TLS + 每设备独立凭证 + 主题 ACL**
- 学生在**自己的后端**上鉴权，后端再做鉴权代理，**学生端不持有 broker 凭证**
- **本项目仓库中已有一套可复用的鉴权与审计后端**（顶盖控制桥接层、设备令牌、时段联锁、指令流水），可作为替代路线，见 [`HARDWARE_DESIGN.md`](HARDWARE_DESIGN.md)

### 7.2 「不占用学校后端资源」的代价是把鉴权与审计全部让渡给了公共节点

一旦发生误操作或事故，**无法回答「是谁、在什么时间、开的罩」**。
在校园安全责任认定场景下，这是**重大缺陷**——尤其当装置可以在无人值守时自动动作。

### 9.1 ⚠️ 「埋地 400mm 化学锚栓」在楼顶无法实施

| 出处 | 原文 |
| --- | --- |
| 明细表 结构材料类 | 镀锌矩形管 100×50×3（塔身立柱与横撑），说明「8 立柱 + 横撑，**埋地 400mm 化学锚栓固定**」 |
| §4.5 材料选型表 | 塔身「防锈、**可埋地**、刚度高、内腔可藏线」 |

楼顶是**已建成的混凝土屋面板**，不存在「埋地」。

**需重新确定基础方案**，且必须由**结构专业人员**确认：

| 待定项 | 说明 |
| --- | --- |
| 固定方式 | 化学锚栓植入屋面板（需避开防水层与保温层）／ 现浇混凝土配重墩 ／ 与女儿墙或结构梁连接 |
| **屋面承载力** | 塔身 + 承力盘 + 双球壳 + 望远镜 + 推杆 ≈ **数百公斤集中荷载**，必须核算楼板承载力与挠度 |
| 防水层破坏与修复 | 锚栓穿透防水层后的**二次防水**做法，否则雨水沿锚栓渗漏，赔的是整栋楼的维修 |
| 配重 vs 锚固 | 若不允许钻孔，只能靠配重抗倾覆——**配重块重量需按风载倾覆力矩反算**（原设计完全没有这一项） |
| 化学锚栓 vs 膨胀螺栓 | 化学锚栓需混凝土达到设计强度且无裂缝；**老旧楼板慎用** |

> 原设计只做了「抗压/抗剪」的隐含假设，**完全没有抗倾覆计算**（见 4.10），这在楼顶是刚性缺口。

### 9.2 ⚠️ 防雷要求显著升级（与 3.3 叠加）

塔顶球壳标高 1600mm，加上楼顶自身高度，将成为**整栋建筑的最高点之一**。

| 问题 | 说明 |
| --- | --- |
| **是否在既有接闪器保护范围内** | 必须查建筑的防雷设计图纸，用滚球法核算球壳、推杆、AP、摄像头是否处于现有避雷针/避雷带的保护范围内 |
| **若不在保护范围内** | 必须**新增接闪器**并接入建筑原有防雷接地网——**不能自打一根独立接地极**（会形成电位差，反而引雷） |
| **等电位连接点** | §4.10 写「两片铝壳、承力盘、塔身用扁铁连成等电位，接地极电阻 ≤10Ω」——楼顶应接入**建筑总等电位端子**，而非独立接地 |
| **雷击对 S50 Pro 的风险** | 即使结构在保护范围内，塔顶的 PoE AP、摄像头、传感器信号线仍是**雷电浪涌入侵通道**，需加信号防雷器（原预算只有电源侧 TVS/压敏） |

> ⚠️ **这是组 9 中风险最高的一条**：原设计按地面空地写的「自打接地极」做法，在楼顶**可能违反防雷规范**。

### 9.3 取电方案失效：不再是「校园路灯回路」

| 出处 | 原文 |
| --- | --- |
| §4.8 | 「优先从**校园路灯回路**或科普角既有市电接一路独立空开 + 漏保」 |

路灯回路在地面；楼顶需要**从楼内配电间引一路电缆上楼顶**。需确认：

- 楼顶是否有**既有检修电源**？容量多少？
- 从配电间到楼顶的**桥架/穿管路径**是否存在？距离多远？（这决定 4.9 那条缺失的电力电缆规格）
- **屋面防水层上如何走线**？明敷还是穿管？谁施工？
- 是否需要**独立计量**或报备后勤？

### 9.4 风载环境恶化，原 8m/s 校核更不成立

地面空地有建筑与树木遮挡，楼顶是**开阔高处的自由风场**，风速显著高于地面。

- 原 §4.6(2) 按 **8m/s** 校核，而 §4.9 保护阈值也是 8m/s（见 4.4）
- 楼顶阵风与**风压高度变化系数**都必须重算，8m/s 大概率不足
- 还需考虑**楼顶特有的狭管效应/涡流**（女儿墙、楼梯间、设备机房附近）

**建议**：至少按当地 50 年一遇基本风压折减后校核，或现场实测一段时间风速后再定保护阈值。

### 9.5 覆盖物与遮挡：从「高杆」变成「女儿墙 + 楼顶设备」

原选址条件是「**需后勤确认南向无高杆遮挡**」。楼顶需要改为核查：

- **女儿墙高度** —— 若 1.2m 高的女儿墙在 600mm 半径处，按 4.3 的算法会遮挡更大仰角（女儿墙顶 = 楼顶面 + 1200mm，比护栏还高）
- **楼顶原有设备**：电梯机房、水箱、空调外机、太阳能板、排烟口、避雷针
- **光污染**：楼顶泛光灯、航空障碍灯、安全出口指示灯
- **热气流**：空调外机/排烟口排出的热气会造成**视宁度恶化**，对深空成像影响很大

> 这一条直接影响「仰角 ≥15°、方位 360°」指标能否成立。

### 9.6 作业安全条件完全改变

| 项 | 地面空地 | 楼顶 |
| --- | --- | --- |
| 高空作业 | 无 | **需要**：临边防护、安全带、作业票 |
| 坠落风险 | 无 | **高**，且球壳下滑路径在楼顶边缘附近时更危险 |
| 材料搬运 | 平地推车 | 需要**吊运或楼梯搬运**（塔身 12m 矩形管、φ1200 承力盘怎么上楼顶？） |
| 夜间调试 | 教师陪护 | 加楼顶照明、临边警戒、**两人以上同行** |
| 天气突变撤离 | 容易 | 楼顶无遮蔽，**雷雨来临前必须撤离** |

**「加工精度不足/调试期人身安全」两项风险的应对措施需要重写。**

### 9.7 审批链条变长，影响工期

原选址只需后勤确认；搬到楼顶通常还需要：

- 学校**基建/总务处**审批（屋面打孔、防水、承重）
- **消防**审批或备案（楼顶新增构筑物、疏散通道）
- 若涉及**防雷设施改动**，可能需要专业机构复核
- 施工期间的**屋面作业许可**

⚠️ **这会直接影响 P2（第 3–6 周 结构材料）与 P5（第 11–12 周 塔体就位）的排期**，且大概率是**关键路径**上的外部依赖——
建议在 P1 阶段就并行启动审批，不要等到 P2 才提。

### 9.8 楼顶环境带来的设备可靠性问题（新增）

| 项 | 说明 |
| --- | --- |
| **雷击风险** | 见 9.2，电子设备损坏概率远高于地面 |
| **夏冬极端温度** | 楼顶表面夏季可达 60℃+、冬季更低，已超出 S50 Pro 标称的 -10℃~40℃；**控制箱内温度必须实测并考虑主动散热** |
| **风沙与积雪** | 楼顶积灰、积雪导致轨道卡滞的概率上升（与 3.7 结冰问题叠加） |
| **振动** | 楼顶设备（空调、风机、电梯机房）的持续振动会影响成像，需核查与望远镜的**共振风险** |
| **维护可达性** | 每次维护都要上楼顶，**OTA 远程升级（组 8 #16）的重要性大幅提升** |
